# dsh-betteroffice

让 DeepSeek Harness（DSH）的 Agent 读取、检查和编辑现有的 Word（`.docx`）、Excel（`.xlsx`）和 PowerPoint（`.pptx`）文件。**编辑默认另存，不改动原文件。**

### Agent 工具

| 工具 | 作用 |
| --- | --- |
| `betteroffice_open` | 打开一个文档，返回任务 ID；路径只在这一步给 |
| `betteroffice_list` | 列出本会话已打开的任务 |
| `betteroffice_checkpoint` | 把当前草稿导出为检查点（`checkpoints/`，绝不覆盖） |
| `betteroffice_deliver` | 把草稿另存为新文件（默认源文件同目录，只允许落在源文件目录或其子目录，同名自动加序号） |
| `betteroffice_replace` | 用户明确要求时就地替换原文件：原件进回收站、新版本落位并校验，失败自动还原 |
| `betteroffice_close` | 关闭任务并释放该文档的 MCP 实例；用户放弃草稿时带 `discard: true` |

打开文档后，该文档的 BetterOffice 工具以 `mcp__bo_<任务ID>__<工具名>` 出现，每个任务一个独立 MCP 实例。

## 怎么用

插件发布并启用后，在 DSH 对话里告诉 Agent 要处理哪个文件、要做什么，以及你想预览、暂存还是导出。给出文件路径即可，不用单独配置文档目录。

例如：

- **只读检查**：「检查 `销售报表.xlsx` 的合计公式，指出可能有问题的单元格，先不要修改。」
- **编辑并另存**：「把 `年度报告.docx` 里的旧部门名称改成『客户运营部』，另存一份，保留原件。」
- **分批编辑**：「先更新 `培训课件.pptx` 的章节标题并保留草稿，等我看完再导出。」

## 原文件会被改动吗？

默认不会。Agent 在副本上编辑，交付时另存为新文件并告诉你保存位置，不覆盖原件或其他已有文件。只想看改动时，可以说「先预览，不要导出」。

只有你明确要求**替换原文件**，并确认这次替换，插件才会把旧文件移入系统回收站，再把已验证的新文件放到原位。确认有两道：Agent 调用时必须声明你已经同意，宿主还会弹一次确认让你点。

替换失败会自动还原：原件进回收站之前先做恢复副本并写事务日志，新文件发布后重新校验哈希；中途崩溃或校验不通过就用恢复副本把原件放回去。不支持回收的文件位置（非 Windows、网络盘等）只能另存，**不会用永久删除换取"替换成功"**。

## 插件设置

**设置 → 插件配置 → BetterOffice** 里有四项（见下表）。安装、更新、回退 BetterOffice MCP 运行时是**你自己的动作**，不走模型：在对话里发送下面的命令。

| 命令 | 作用 |
| --- | --- |
| `/betteroffice` 或 `/betteroffice 状态` | 看当前用的运行时版本、已安装的版本、Node 版本是否够（需要 22.12.0 及以上） |
| `/betteroffice 安装 [版本]` | 装到插件私有目录 `<DSH 主目录>/betteroffice/runtime/<版本>/`，不动全局 npm，也不改 PATH；不带版本号时装最新版 |
| `/betteroffice 检查更新` | 只查询 npm 上的最新版本，不会自动升级 |
| `/betteroffice 更新 [版本]` | 装新版本并把它设为之后新打开文档的默认版本；已打开的任务继续用原来的版本 |
| `/betteroffice 回退 <版本>` | 把默认版本切回一个已经装过的版本 |

多个版本会并排保留，可以随时回退。

| 设置 | 选项 |
| --- | --- |
| **是否使用工作文件夹** | **不使用**：不在原文件旁创建工作文件夹；**自动（默认）**：Agent 需要多轮存档时创建（`betteroffice_open` 带 `workspace: true`）；**强制使用**：每次编辑都创建。只读任务不创建。 |
| **工作完成后删除工作文件夹** | **禁用**：不自动删除；**自动（默认）** 与 **开启**：关闭任务时，若草稿已有已验证的交付（或 Agent 声明放弃草稿），且目录里没有未登记文件，就删掉目录。 |
| **Node.js 路径** | 留空时从 `PATH` 里找第一个 `node`；BetterOffice 要求 22.12.0 及以上。 |
| **运行时版本** | 由 `/betteroffice 安装`、`更新`、`回退` 写入；留空表示还没装，此时打开文档会提示先安装。 |

工作文件夹在原文件旁，以 `dsh-` 开头，供 Agent 分批存档、下次继续。最终文件会保存到工作文件夹之外。如果之后还要修改，可以告诉 Agent「请保留工作文件夹」。

自动清理有三道安全闸：必须先有**已验证的交付**（或你明确放弃草稿），目录里不能有你或别的程序新增的文件，并且台账必须证明这个目录是插件创建的。任何一条不满足就保留目录，原因写进日志。

## 已知限制

- BetterOffice MCP 会同时暴露 `office_export`（写文件）和 `office_files`（列目录）。插件在调用前把它们拦掉：前者只能通过 `betteroffice_deliver` / `betteroffice_replace` 使用，后者直接拒绝。工具名仍会出现在 `mcp__bo_<任务ID>__*` 里，但调用会被拒绝并给出改用哪条工具。
- 替换原文件依赖系统回收站：非 Windows 平台、网络盘等场景只能另存，不会降级成永久删除。
- 「自动」与「开启」两种清理档位目前的判定完全相同，差别留给后续版本（例如由 Agent 明确表态保留时跳过）。

## 关于隐私

BetterOffice 在本机处理文件，但为完成任务而读取的文字、表格内容或预览，仍可能发送给当前 Agent 使用的模型。
